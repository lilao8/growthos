# Dispatch 9：Portfolio Polish

## 目标

完成 MVP 展示质量、跨模块一致性和求职作品集叙述。

## 前置条件

Dispatch 8 的测试与验收已通过，用户已明确确认执行本阶段。读取此前报告，确认相关接口与当前实现一致。

开始前阅读 `README.md`、`CLAUDE.md`、`docs/00-architecture.md`、本文件与相关代码；以当前项目为准，不假设前序实现。全局愿景不等于本阶段授权。

## 范围

- 统一组件、视觉层级、数字格式、按钮文案、loading / empty / error / retry；修复桌面/平板/手机布局。
- Accessibility：键盘、焦点、表单标签、图表摘要、可读对比度、状态提示；Performance：生产构建下记录关键页面测量方法、结果和改进。
- 校验 15+ SKU、90 天数据、审计分数、各页面指标、推荐证据与持久化一致；无随机漂移或冒充真实业绩。
- Dashboard 跨模块链接完整，展示前面各阶段已交付的全部指标与摘要；不得补一套独立假数据。
- 增加 /about-project：开发动机、独立站运营问题、解决方法、SEO/GEO/Content/Analytics/Funnel/Recommendations 关系、模型局限。
- 扩充根 README：项目背景、业务问题、目标、功能、实际技术架构、SEO/GEO 设计、数据模型、核心指标、安装/运行/测试、截图位置、未来规划；保留本任务索引。
- 保存真实应用截图到 docs/screenshots/，提供 3–5 分钟演示路径与面试讲解提纲。只能讲模拟结果，不能写“已提升真实收入/排名”。
- 回归流程：商品 SEO 编辑→审计 stale→重新 SEO/GEO 审计→内容计划→Analytics→Funnel→Recommendation 完成并刷新。

## 明确禁止提前实现的内容

- 不新增大型业务功能、真实 API、登录权限、支付、自动化发布或 AI 生成服务。
- 不为展示修改测试结果或编造优化成果；不未经用户授权部署。
- 不进入后续 Dispatch；若当前任务依赖尚未实现的后续能力，使用有说明的占位或接口，不扩展实现。

## 验收标准

- 全新安装、启动、seed/reset 和测试说明可复现；所有导航与跨模块深链可用。
- 375/768/1440px 检查，重要流程键盘可达；性能检查记录实际环境和结果，不虚报 Lighthouse 等分数。
- 关键 E2E 回归涵盖真实持久化、过滤、错误恢复；所有 unit/integration/e2e、lint、typecheck、production build 通过。
- README、截图、/about-project 与实现一致，未实现功能明确列未来规划。
- 输出最终 MVP 状态、完整测试证据、剩余限制和可直接演示的路径；没有已知阻塞缺陷才标 MVP 完成。

## 测试命令

从应用根目录运行；Dispatch 0 必须先建立这些真实脚本，后续阶段沿用。约定 Vitest 与 Playwright，已有不同框架则按阶段 0 记录使用等价命令。

```bash
npm run lint
npm run typecheck
npm run test -- --run
npm run test:integration -- --run
npm run test:e2e
npm run build
```

按上面的验收场景增加当前阶段测试，同时保留此前回归。命令失败须修复并重新运行；无环境、无测试用例、跳过测试不能计为通过。当前阶段报告中记录实际命令、结果及浏览器验收证据。

## 完成后的汇报格式

保存到 `docs/reports/dispatch-09.md`，并在会话输出：

```text
Dispatch 9 — PASS / FAIL / BLOCKED

1. 本次完成内容：对应范围和验收项逐条说明。
2. 修改的核心文件：路径 + 修改目的。
3. 测试结果：命令、实际通过/失败/跳过数量、构建结果；附关键日志或证据位置。
4. 验收证据：关键操作、数据核对、截图或人工检查结果；区分已实测与未运行。
5. 当前已知问题：缺陷、环境限制、必要偏离及原因；没有则明确“无已知阻塞问题”。
6. 下一 Dispatch 建议：MVP 已完成时提供演示与后续候选事项；不自动开始新功能或发布。
7. 状态：已停止，等待用户确认；如未通过则明确本阶段尚未完成。
```
