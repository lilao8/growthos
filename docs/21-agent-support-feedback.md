# Dispatch 21 · 客服反馈分析

## 输入与口径

- 固定的模拟工单使用唯一 ID、UTC 创建日、摘要、可选 SKU 和可选完整商品名。沿用 GrowthOS 的固定截止日和 7、30、90 天窗口。
- 规则按摘要分为物流、尺码与适配、商品质量、退换货、商品信息。没有明确线索或命中多个分类进入待分类。
- 明确 SKU 优先。缺 SKU 时只接受唯一完整商品名。未知 SKU 和多义名称保留为未匹配。操作员查数可以用唯一商品名前缀，这不影响工单归属。
- 同一 ID 计一次，冲突的重复记录使用首条。已匹配 SKU 按件数降序、SKU 升序排列。未匹配件数单列。统计按工单创建日，不用流量、订单或会话充当分母。

## 使用流程

- `/support` 查看完整排名和工单，可按窗口、SKU 与问题分类筛选。
- Ops Agent 通过只读工具读取排名和已计算的件数。回答列出排名靠前的三款，每款至多列出两个主要分类，数字链接打开同一筛选的工单列表。
- 一次性条件只作用于查询。明确收窄的追问更新 SKU 范围并保留日期。已知 SKU 没有工单时显示 0。查不到唯一 SKU 时提示无法匹配。数据没有营销渠道归因。
- 首版使用模拟数据。实时调用沿用原开关。客服平台接入、自动回复和状态写入不在范围内。

## 验收

1. Agent 查 30 天内的 SKU 排名与问题分布，数字可回到匹配工单。
2. 追问 Ridgeline 2P 保持日期窗口，物流件数与工单页一致。
3. 去重、窗口两端、歧义、分类冲突和空窗口有测试。
4. 工单写请求被拒绝，测试使用替身模型。
